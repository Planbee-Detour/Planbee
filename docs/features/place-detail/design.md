# UI/UX 명세: 관광지 상세 (`place-detail`)

- 작성일: 2026-08-29
- 작성 역할: ux-designer
- 근거: 사용자 확정안(2026-08-29), `docs/design/planbee.pen`,
  `docs/design/planbee-design-prompt.md`, `docs/conventions/mobile.md`
- 범위: 공통 관광지 상세 화면의 구조와 네 가지 상태. API 계약과 실제 길찾기·북마크 동작은 범위 밖이다.
- 이 문서의 큰따옴표 안 문구는 구현 시 그대로 사용한다 (`mobile.md` M-7).

## 1. 내비게이션과 동작

- 홈, AI 추천, 탐색, 저장 등 관광지 정보를 표시하는 모든 화면에서 관광지 항목을 탭하면
  `PlaceDetailScreen(placeId)`를 현재 스택에 push한다.
- 상단 왼쪽 "뒤로" 버튼과 iOS 스와이프 백은 진입했던 화면으로 pop한다.
- Android 하드웨어 뒤로가기도 같은 화면으로 pop한다.
- 상세 화면에는 하단 탭 바를 표시하지 않는다.
- 상단 북마크 버튼은 이번 시각화에서 **동작 미정인 더미 컨트롤**이다. 인증과 API가 확정되기 전에는
  저장 상태를 낙관적으로 바꾸거나 로그인 화면으로 이동시키지 않는다.
- 하단 "여기로 가기" 버튼도 **동작 미정인 더미 컨트롤**이다. 지도 앱 연결, 앱 내부 길찾기,
  일정 추가 중 어느 동작으로도 확정하지 않는다.
- "Planbee에게 물어보기"는 장소 맥락을 포함한 AI Assistant 진입을 의도하지만, 이번 범위에서는
  시각적 CTA만 제공하며 실제 전이는 후속 계약에서 확정한다.

## 2. 공통 화면 구조

- 기준 폭 390pt, 세로 스크롤 화면. 배경은 `Color/Neutral/Background`.
- 히어로 이미지 300pt. 이미지 위에 최소 44×44pt의 뒤로가기와 북마크 버튼을 둔다.
- 본문 순서:
  1. 카테고리·운영 상태
  2. 관광지명
  3. 주소·운영 정보·거리
  4. 태그
  5. 짧은 소개
  6. "Planbee 추천 이유"
  7. "위치" 지도
  8. "한국관광공사 제공" 출처
- 주소·운영 정보·거리·태그·소개·AI 추천 이유·이미지가 누락되면 그 항목 전체를 숨기고
  다음 항목을 위로 당긴다. 빈 행, 하이픈, "정보 없음"을 표시하지 않는다.
- 지도 좌표가 없으면 위치 섹션 전체를 숨긴다.
- 대표 이미지가 없으면 히어로 영역에 `image` 아이콘과 "등록된 사진이 없어요"를 표시한다.
- 하단 CTA 바는 화면 하단 안전영역 위에 고정하고, 스크롤 콘텐츠의 마지막에 같은 높이의 여백을 둔다.

## 3. 화면 상태

### 3.1 정상 — `Screen 04a — Place Detail / 정상`

- 예시 데이터는 국립현대미술관 서울을 사용한다.
- 히어로 이미지, "역사 · 문화", "운영 중", 관광지명, 주소, 운영시간, 거리, 태그,
  짧은 소개, AI 추천 이유, 지도, 출처를 표시한다.
- 하단 버튼: "Planbee에게 물어보기", "여기로 가기".
- 누락된 선택 필드는 §2의 숨김 규칙을 적용하며 화면 전체를 빈 상태로 바꾸지 않는다.

### 3.2 로딩 — `Screen 04b — Place Detail / 로딩`

- 뒤로가기만 즉시 사용할 수 있다. 북마크와 하단 CTA는 표시하지 않는다.
- 히어로, 제목 두 줄, 정보 행 세 줄, 본문, AI 추천 카드, 지도 위치에 중립색 스켈레톤을 표시한다.
- 스켈레톤은 반복 애니메이션을 강제하지 않는다. 동작 줄이기가 꺼져 있을 때만 약한 opacity pulse를 허용한다.
- 스크린리더 문구: "장소 정보를 불러오는 중".

### 3.3 비어있음 — `Screen 04c — Place Detail / 찾을 수 없음`

- 장소 ID가 더 이상 유효하지 않거나 공개 중인 관광지가 아닐 때 표시한다.
- 본문 중앙에 `map-pin-off` 아이콘과 다음 문구를 표시한다.
  - 제목: "장소 정보를 찾을 수 없어요"
  - 본문: "장소가 삭제되었거나 현재 공개되지 않았어요."
  - 버튼: "이전 화면으로"
- 버튼은 현재 화면을 pop한다. 하단 CTA 바와 북마크는 표시하지 않는다.

### 3.4 오류 — `Screen 04d — Place Detail / 오류`

- 네트워크 또는 서버 오류로 상세 정보를 받지 못했을 때 표시한다.
- 본문 중앙에 `wifi-off` 아이콘과 다음 문구를 표시한다.
  - 제목: "장소 정보를 불러오지 못했어요"
  - 본문: "연결을 확인하고 다시 시도해 주세요."
  - 주 버튼: "다시 시도"
  - 보조 버튼: "이전 화면으로"
- "다시 시도"는 동일 관광지 ID로 다시 요청한다. "이전 화면으로"는 pop한다.
- 이전 상세 데이터를 이미 표시한 뒤 재검증에 실패한 경우에는 전체 오류 화면으로 바꾸지 않고
  기존 데이터를 유지한다. 이 상태는 최초 로딩 실패에만 사용한다.

## 4. 컴포넌트

| 영역 | 재사용/신규 | 비고 |
|---|---|---|
| 상태바 | `Layout/StatusBar` 재사용 | 히어로 위 밝은 아이콘 변형 |
| 뒤로가기·북마크 | 화면 전용 | 44×44pt 터치 영역 |
| 태그 | `Chip/QuickAction` 변형 재사용 | 정보 태그이므로 선택 동작 없음 |
| AI 추천 이유 | `AI/Identity` 재사용 | 구조화된 관광 정보와 시각적으로 구분 |
| 하단 보조 CTA | `Button/Secondary` 재사용 | "Planbee에게 물어보기" |
| 하단 주 CTA | `Button/Primary` 재사용 | "여기로 가기", 동작 미정 |
| 재시도·이전 화면 | 기존 버튼 재사용 | 오류·비어있음 상태 |
| 스켈레톤 | 화면 전용 | 기존 neutral/background 토큰만 사용 |

신규 색·타이포·간격 토큰은 추가하지 않는다.

## 5. 접근성

- 모든 터치 대상은 최소 44×44pt다.
- 아이콘 버튼 레이블: "뒤로", "북마크". 저장 상태가 확정되면 "북마크 추가"/"북마크 삭제"로 세분화한다.
- 지도는 장식 이미지가 아니라면 `accessibilityLabel="국립현대미술관 서울 위치"`처럼 관광지명을 포함한다.
- 동적 폰트 사용 시 제목·설명은 줄 수를 고정하지 않고 높이가 늘어난다.
- 운영 상태는 색만으로 구분하지 않고 "운영 중" 문구를 함께 표시한다.
- 오류와 빈 상태는 화면 진입 시 제목을 읽어준다.

## 6. 화면별 인수조건

| AC | 조건 |
|---|---|
| AC-PD-1 | 어느 관광지 카드에서 진입해도 상세 화면이 push되고 뒤로가면 원래 화면으로 돌아간다. |
| AC-PD-2 | 정상 응답은 한 화면 응답만으로 §2의 모든 영역을 구성하며 앱에서 데이터를 조합하지 않는다. |
| AC-PD-3 | 선택 정보가 없으면 해당 영역만 숨기고 나머지 화면은 정상 표시한다. |
| AC-PD-4 | 로딩·정상·비어있음·오류 상태가 각각 존재한다. |
| AC-PD-5 | 최초 요청 오류에서 다시 시도하거나 이전 화면으로 돌아갈 수 있다. |
| AC-PD-6 | 북마크와 "여기로 가기"는 후속 결정 전까지 동작을 확정하지 않는다. |

## 7. 후속 결정

- `여기로 가기`: 외부 지도 앱, 앱 내부 길찾기, 일정 추가 중 선택 필요.
- 북마크: 인증 전 로컬 저장 여부와 비로그인 사용자 처리 필요. 인증·API 연결 후에는
  "로그인이 필요한 기능이에요." 안내 후 로그인으로 이동하는 안을 우선 검토한다.
- 데이터 확장: 초기에는 공통 필드만 사용하고, 추후 DB의 `additional_info` 또는 유형별 상세 구조가
  확정되면 운영시간 상세·편의시설·이용요금 등을 별도 섹션으로 추가한다.
