# PRD: 관광지 상세

- 기능 슬러그: `place-detail`
- 작성일: 2026-08-29

## 배경 / 문제

사용자는 홈·지도·검색·저장 등에서 발견한 관광지의 상세 정보를 한 화면에서 확인하고 원래 화면으로 돌아갈 수 있어야 한다.

## 목표

- 어느 관광지 카드에서든 동일한 `place_id` 기반 상세 화면으로 진입한다.
- API 서버 준비 전에는 미래 계약과 같은 로컬 JSON fixture로 네 가지 화면 상태를 구현한다.

## Out of scope

- 실제 서버 호출과 서버 구현
- 실제 지도 SDK, 북마크 저장, 길찾기, AI 대화 전이

## 유저 스토리와 인수조건

### US-1. 여행자로서 관광지 정보를 자세히 확인하고 싶다

| ID | 인수조건 |
|---|---|
| AC-PD-1 | 관광지 카드를 누르면 해당 `place_id`의 상세 화면이 push된다. |
| AC-PD-2 | 상세 화면은 한 상세 응답만으로 모든 영역을 표시한다. |
| AC-PD-3 | 선택 정보가 없으면 해당 영역만 숨긴다. |
| AC-PD-4 | 로딩·정상·찾을 수 없음·오류 상태가 존재한다. |
| AC-PD-5 | 오류 화면에서 다시 시도하거나 이전 화면으로 돌아갈 수 있다. |
| AC-PD-6 | 북마크와 CTA는 동작하지 않는 시각적 컨트롤이다. |

## 제약

- API 경계 데이터는 `snake_case`다.
- 현재는 계약과 동일한 로컬 JSON을 사용하고 네트워크 요청을 하지 않는다.
- Root Stack 안에 Bottom Tabs를 두며 상세에는 탭 바를 표시하지 않는다.

## 열린 질문

- API 서버 준비 후 로컬 fixture를 실제 조회 훅으로 교체한다.
- 지도·북마크·길찾기·AI CTA 동작은 후속 기능에서 확정한다.
