# UI/UX 명세: 실시간 변수 기반 Plan B 추천 (`plan-b-recommendation`)

- 작성일: 2026-08-29
- 근거: 사용자 확정안 1.B·2.C·3.A·4.C·5.A, `PRD.md`, `docs/product/competition-theme.md`
- 시연 fixture: 경복궁·북촌 산책을 포함한 오늘의 유연한 일정, 20분 뒤 비 시작 예상, 경복궁 오늘 휴궁

## 1. 전체 흐름

1. 홈은 실시간 변수를 감지한 뒤 일정 상태에 따라 `NEEDS_CONFIRMATION`, `CONFIRMED`, `NO_IMPACT`로 나눈다.
2. `UNKNOWN`인 유연한 일정이 있으면 영향을 단정하지 않고 "남은 일정 확인하기"를 표시한다.
3. 사용자가 영향 가능 일정마다 "다녀왔어요" 또는 "아직이에요"를 선택한다.
4. 모두 완료했다면 변경할 일정이 없음을 알리고 홈으로 돌아간다.
5. 남은 일정이 확인되면 홈에 영향 확정 카드와 "대체 계획 확인하기"를 표시한다.
6. 사용자가 버튼을 누르면 `PlanBRecommendationScreen`을 push하고 추천 생성 상태를 표시한다.
7. 기본 결과로 국립현대미술관 서울 한 곳 교체안을 표시한다.
8. 사용자는 그대로 교체하거나 "코스로 다시 짜기"를 선택한다.
9. "이 계획으로 변경"을 누르면 확인 화면을 거쳐 fixture 일정을 교체한다.

사용자 확인 전에는 기존 일정을 바꾸지 않는다.

## 2. 일정 진행 상태와 영향 판정

### 시간 유형

| 유형 | 의미 | 진행 판정 |
|---|---|---|
| `FIXED` | 예약·열차처럼 시작 시각이 고정된 일정 | 명시적 상태와 유효 시각을 함께 사용 |
| `TIME_WINDOW` | 오전·오후 또는 운영시간 안에 수행하는 일정 | 명시적 상태와 남은 시간 범위를 함께 사용 |
| `FLEXIBLE` | 날짜만 정해지고 실행 시각·순서가 자유로운 일정 | 현재 몇 번째인지 추정하지 않고 사용자 확인 사용 |

### 진행 상태

- `PLANNED`: 아직 방문하지 않은 것으로 확인됨
- `IN_PROGRESS`: 현재 수행 중인 것으로 확인됨
- `COMPLETED`: 완료되어 추천 대상에서 제외됨
- `SKIPPED`: 건너뛰어 추천 대상에서 제외됨
- `CANCELLED`: 취소되어 추천 대상에서 제외됨
- `UNKNOWN`: 완료 여부를 알 수 없어 사용자 확인이 필요함

### 영향 수준

| 수준 | 조건 | UI 원칙 |
|---|---|---|
| `NEEDS_CONFIRMATION` | `UNKNOWN`이거나 시각만으로 상태를 추정함 | 가능성만 알리고 진행 상태를 질문한다. 영향 확정 표현과 푸시는 사용하지 않는다. |
| `CONFIRMED` | `PLANNED` 또는 `IN_PROGRESS`임이 명시적으로 확인됐고 변수와 겹침 | 영향받는 일정과 Plan B 진입 버튼을 표시한다. |
| `NO_IMPACT` | 완료·건너뜀·취소되었거나 변수와 겹치지 않음 | Plan B 카드를 표시하지 않는다. |

종료 시각이 지났다는 이유만으로 완료 처리하지 않는다. 진행률은 "5개 중 2개 완료"처럼
확인된 상태를 기준으로 표시하며, `FLEXIBLE` 일정에는 "현재 3번째 일정" 같은 표현을 사용하지 않는다.

## 3. 화면: 홈 / 변수 감지와 일정 확인

### 확인 필요 — `Screen 17a — Home / 영향 확인 필요`

- 기존 `Screen 02 — Home` 구조에서 인사말 아래, AI 액션 카드 위에 낮은 강도의 상황 카드를 표시한다.
- 카드 문구:
  - 배지: "날씨 변화가 예상돼요"
  - 제목: "20분 뒤 비가 올 예정이에요"
  - 본문: "오늘 계획한 야외 일정 중 아직 남은 일정이 있나요?"
  - 버튼: "남은 일정 확인하기"
- 아직 확인되지 않은 장소가 "영향받는다"거나 일정 변경이 필요하다고 단정하지 않는다.

### 일정 진행 확인 — `Screen 17b — 일정 진행 확인`

- 상단 제목: "아직 남은 야외 일정이 있나요?"
- 본문: "완료한 일정은 Plan B 추천에서 제외할게요."
- 확인된 진행률: "야외 일정 2개 · 완료 여부 확인 필요"
- 영향 가능 일정마다 `Schedule/ProgressConfirmationRow`를 표시한다.
  - 장소명: "경복궁" / "북촌 산책"
  - 보조 정보: "오늘 · 유연한 일정"
  - 선택: "다녀왔어요" / "아직이에요"
- 모든 항목을 선택하기 전에는 "확인 완료" 버튼을 비활성화한다.
- 화면을 닫으면 상태를 확정하지 않고 `UNKNOWN`으로 유지한다.

### 영향 없음

- 모든 영향 가능 일정에 "다녀왔어요"를 선택한 경우:
  - 제목: "오늘 야외 일정은 모두 완료했어요"
  - 본문: "비 예보로 변경할 일정은 없어요."
  - 버튼: "홈으로"
- 홈으로 돌아가면 변수 카드를 숨긴다.

### 영향 확정 — `Screen 17c — Home / 영향 확정`

- 기존 `Screen 02 — Home` 구조를 유지한다.
- 인사말 아래, AI 액션 카드보다 위에 `Situation/DisruptionCard`를 표시한다.
- 카드 문구:
  - 배지: "일정에 영향을 주는 변수가 있어요"
  - 제목: "20분 뒤 비가 오고, 경복궁은 오늘 휴궁이에요"
  - 본문: "오후 2시 경복궁 일정의 대체 계획을 준비할 수 있어요."
  - 버튼: "대체 계획 확인하기"
- 비와 휴무를 아이콘과 문구로 함께 표현한다.
- 카드는 사용자가 닫지 않는 한 일정 시작 전까지 유지한다.

### 로딩

- 변수 확인 중에는 기존 홈을 유지하고 지역 문구 옆에 작은 로딩 상태만 표시한다.
- 확정되지 않은 경고 카드를 먼저 표시하지 않는다.

### 비어있음

- 영향받는 일정이 없으면 변수 카드를 표시하지 않고 기존 홈을 그대로 유지한다.

### 오류

- 변수 확인 실패만으로 홈 전체 오류를 표시하지 않는다.
- 기존 홈을 유지하고 자동 감지 카드를 생략한다. 사용자는 빠른 도움 기능을 계속 사용할 수 있다.

## 4. 화면: Plan B 추천

### 로딩 — `Screen 17d — Plan B / 추천 생성 중`

- 상단 제목: "대체 계획 찾기"
- 뒤로가기 가능. 하단 탭 바는 표시하지 않는다.
- AI Identity와 문구를 표시한다.
  - 제목: "Planbee가 새로운 계획을 찾고 있어요."
  - 본문: "날씨, 운영 상태, 이동 시간과 취향을 함께 확인하고 있어요."
- 진행 단계:
  1. "영향받는 일정 확인"
  2. "방문 가능한 장소 찾기"
  3. "시간과 동선 검토"
  4. "추천 근거 정리"
- 완료되지 않은 내부 추론 문장이나 임시 후보는 노출하지 않는다.

### 정상·장소 교체 — `Screen 17e — Plan B / 장소 교체`

- 상황 요약:
  - 제목: "경복궁 일정을 바꿔야 해요"
  - 근거: "20분 뒤 비 시작" · "경복궁 오늘 휴궁"
- 기존 계획:
  - "14:00 경복궁"
  - "방문 불가 · 오늘 휴궁"
- 추천 계획:
  - "14:10 국립현대미술관 서울"
  - "실내 · 운영 중 · 도보 12분"
- 추천 설명:
  - 헤드라인: "비를 피해 이어가는 역사·문화 일정"
  - 요약: "경복궁과 성격이 비슷한 실내 문화 공간이며, 현재 위치와 다음 일정에서 크게 벗어나지 않아요."
- 검증 가능한 근거:
  - "비가 와도 이용 가능한 실내 장소"
  - "현재 위치에서 도보 12분"
  - "남은 2시간 안에 관람 가능"
  - "역사·문화 취향과 유사"
- 주의사항:
  - "다음 일정이 약 12분 늦어질 수 있어요."
- 버튼:
  - 주 버튼 "이 계획으로 변경"
  - 보조 버튼 "코스로 다시 짜기"
  - 텍스트 버튼 "다른 장소 보기"

### 정상·코스 재구성 — `Screen 17f — Plan B / 코스 재구성`

- 제목: "남은 2시간을 다시 구성했어요"
- 시간순 코스:
  1. "14:10 국립현대미술관 서울" · "관람 80분"
  2. "15:38 인근 카페" · "휴식 30분"
  3. "16:20 다음 일정으로 이동" · "이동 20분"
- 시간 계산:
  - "이동 20분 + 관람 80분 + 휴식 30분 + 다음 일정 이동 20분 + 여유 10분"
  - "총 160분 / 사용 가능 180분"
- 검증 근거와 주의사항은 §4 장소 교체와 같은 형식을 사용한다.
- 버튼:
  - 주 버튼 "이 계획으로 변경"
  - 보조 버튼 "장소 하나만 바꾸기"

### 비어있음 — `Screen 17g — Plan B / 대안 없음`

- 아이콘: `search-x`
- 제목: "조건에 맞는 대체 계획을 찾지 못했어요"
- 본문: "이동 범위나 방문 시간을 넓히면 다른 계획을 찾을 수 있어요."
- 주 버튼: "조건 완화해서 다시 찾기"
- 보조 버튼: "이전 화면으로"
- 조건 완화는 실제 변경 전에 다음 값을 보여준다.
  - 도보 15분 → 25분
  - 다음 일정 지연 허용 20분 → 40분

### 오류 — `Screen 17h — Plan B / 오류`

- 아이콘: `wifi-off`
- 제목: "대체 계획을 만들지 못했어요"
- 본문: "연결을 확인하고 다시 시도해 주세요."
- 주 버튼: "다시 시도"
- 보조 버튼: "이전 화면으로"

## 5. 화면: 변경 완료

### 정상 — `Screen 17i — Home / Plan B 적용 완료`

- 홈으로 pop한 뒤 상단에 성공 배너를 표시한다.
  - 제목: "Plan B로 일정을 변경했어요"
  - 본문: "오후 2시 일정이 국립현대미술관 서울로 바뀌었어요."
  - 버튼: "변경된 일정 보기"
- 토스트만 사용하지 않고 변경 결과를 다시 확인할 수 있는 배너를 제공한다.

### 로딩·비어있음·오류

- 일정 저장 API가 생기기 전 fixture 단계에서는 즉시 성공한다.
- 후속 계약에서는 저장 중 버튼 비활성화, 저장 오류와 재시도를 별도로 정의한다.

## 6. 상태 전이

| 출발 | 조건/행동 | 도착 |
|---|---|---|
| 홈 | 변수와 겹치는 일정 상태가 `UNKNOWN` | 영향 확인 필요 카드 |
| 영향 확인 필요 카드 | "남은 일정 확인하기" | 일정 진행 확인 |
| 일정 진행 확인 | 모두 "다녀왔어요" | 영향 없음 안내 → 홈 |
| 일정 진행 확인 | 하나 이상 "아직이에요"이고 변수와 겹침 | 홈 / 영향 확정 |
| 홈 / 영향 확정 | "대체 계획 확인하기" | Plan B / 추천 생성 중 |
| 추천 생성 중 | 추천 성공 | Plan B / 장소 교체 |
| 장소 교체 | "코스로 다시 짜기" | Plan B / 코스 재구성 |
| 장소 교체·코스 재구성 | "이 계획으로 변경" | Home / Plan B 적용 완료 |

`NEEDS_CONFIRMATION` 단계에서는 알림 푸시를 보내지 않는다. 푸시 자체는 MVP 범위 밖이며,
후속 구현에서도 `CONFIRMED` 영향만 발송 후보로 삼는다.

## 7. 추천 결정 기록

화면은 LLM의 자유로운 사고 과정을 표시하지 않는다. 서버가 다음 순서로 확정한 결과만 표시한다.

1. 감지 이벤트: `RAIN_EXPECTED`, `PLACE_CLOSED`
2. 영향 일정: `14:00 경복궁`
3. 필수 제약: 운영 중, 실내, 시간 예산 내, 다음 일정 도착 가능
4. 점수 요소: 장소 유사도, 취향, 상황, 동선, 시간, 혼잡도
5. 근거 코드: `RESOLVES_WEATHER_CONFLICT`, `PLACE_OPEN`, `SHORT_DETOUR`,
   `FITS_AVAILABLE_TIME`, `SIMILAR_INTEREST`
6. 주의 코드: `SLIGHT_SCHEDULE_DELAY`

LLM은 확정된 근거 코드를 두 문장 이내로 정리한다. 입력에 없는 사실·숫자·장소는 추가하지 않는다.
검증 실패 시 같은 근거의 서버 템플릿 문구를 표시한다.

## 8. 컴포넌트

| 영역 | 재사용/신규 | 비고 |
|---|---|---|
| 상태바·상단 바 | 기존 재사용 | `Layout/StatusBar`, `Layout/NavBar` |
| 변수 감지 카드 | 신규 `Situation/DisruptionCard` | 기존 색상 토큰만 사용 |
| 일정 진행 확인 | 신규 `Schedule/ProgressConfirmationRow` | 장소별 완료 여부를 두 선택지로 확인 |
| AI 상태 | `AI/Identity` 재사용 | 생성 중 정체성 표시 |
| 기존·추천 일정 | 기존 `Layout/ListRow` 변형 | 상태 문구 포함 |
| 추천 근거 | 신규 `Reason/EvidenceRow` | 체크 아이콘+근거 문구 |
| 주의사항 | `Feedback/Banner` 재사용 | 오류가 아닌 trade-off |
| CTA | `Button/Primary`, `Button/Secondary` 재사용 | 사용자 확인 후 적용 |

신규 색·타이포·간격 토큰은 추가하지 않는다.

## 9. 접근성

- 모든 터치 영역은 최소 44×44pt다.
- 경고는 색뿐 아니라 "비", "휴궁" 문구와 아이콘으로 표현한다.
- 로딩 화면의 스크린리더 문구는 "Planbee가 새로운 계획을 찾고 있어요"다.
- 추천 근거는 목록으로 읽히며 주의사항은 추천 근거 다음에 읽힌다.
- 일정 변경 완료 시 성공 배너 제목으로 포커스를 이동한다.
- "다녀왔어요"와 "아직이에요"는 선택 상태를 색뿐 아니라 체크 아이콘과 접근성 상태로 전달한다.
