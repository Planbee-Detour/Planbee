# PRD: 주변 장소 탐색

- 기능 슬러그: `nearby-places`
- 작성일: 2026-08-29
- 개정: 2026-09-08 — **서버 조회 도입** (로컬 fixture → 실데이터). 아래 "서버 조회" 절과
  AC-NP-7~10 추가. 데이터 소스·필터·상위 N 은 사람 결정으로 확정됨.
  (같은 날 재개정 — 카카오 로컬 REST 에 place_id 조회가 없어 데이터 소스를 TourAPI 로 통일)

## 배경 / 문제

홈의 제한된 장소 카드만으로는 주변 선택지를 충분히 비교하기 어렵고, 지도 마커만으로는 장소를 식별하기 어렵다.

## 목표

- 홈의 "더보기"에서 주변 장소 목록으로 진입한다.
- 목록과 지도를 전환하고, 지도 마커 선택 시 장소 카드를 함께 표시한다.
- 어느 카드에서든 기존 장소 상세 화면으로 진입한다.
- **현재 위치 기준 주변 장소를 실제 데이터로 조회한다** (2026-09-08).

## 서버 조회 (2026-09-08 확정)

- **데이터 소스**: 한국관광공사 TourAPI(KorService2) 단일. 주변은 `locationBasedList2`,
  상세는 `detailCommon2`(+ `detailIntro2`). 카카오 로컬은 place_id 로 단일 장소를 조회하는
  REST 엔드포인트가 없어 상세를 이을 수 없으므로 쓰지 않는다.
- **필터**: 콘텐츠 유형 다중 선택 — `관광지`·`문화시설`·`레포츠`·`숙박`·`쇼핑`·`음식점`
  (TourAPI contentTypeId). 정렬은 거리순 고정.
- **상위 N**: 기본 15개, 최대 45개. 검색 반경 기본 2km.
- **`place_id`**: `tour:<contentid>` 형식이라 어느 카드에서든 상세로 이을 수 있다.
- 계약: `docs/features/nearby-places/contract.yaml` · `docs/features/place-detail/contract.yaml`.

## Out of scope

- 실제 지도 SDK와 지도 타일, 위치 권한 추가
- 지도 이동에 따른 재검색("이 지역에서 다시 찾기"), 클러스터링
- **"운영 중" 필터** — 카카오가 영업시간을 주지 않아 신뢰할 수 있게 판정할 수 없다.
  `status_label` 은 TourAPI 매칭 시에만 표시하고, 필터 컨트롤은 두지 않는다.
- 키워드 검색, 페이지네이션(무한 스크롤) — 상위 N 고정 목록이다.

## 유저 스토리와 인수조건

### US-NP-1. 여행자로서 주변 장소를 비교하고 싶다

| ID | 인수조건 |
|---|---|
| AC-NP-1 | 홈의 "더보기"를 누르면 주변 장소 화면이 push되고 목록이 기본 표시된다. |
| AC-NP-2 | "목록"과 "지도"를 누르면 같은 장소 집합의 표현이 전환된다. |
| AC-NP-3 | 지도 마커를 누르면 해당 장소의 하단 카드가 선택 상태로 표시된다. |
| AC-NP-4 | 목록 또는 지도 카드를 누르면 해당 `place_id` 상세 화면이 push된다. |
| AC-NP-5 | 로딩·정상·비어있음·오류 상태가 존재한다. |
| AC-NP-6 | 오류 상태에서 다시 시도하거나 이전 화면으로 돌아갈 수 있다. |

### US-NP-2. 여행자로서 실제 주변 장소를 카테고리로 좁혀 보고 싶다 (2026-09-08)

| ID | 인수조건 |
|---|---|
| AC-NP-7 | 현재 위치 좌표로 조회하면 반경 2km 안의 장소가 거리순으로 최대 15개 표시된다. |
| AC-NP-8 | 카테고리 필터를 선택하면 해당 유형의 장소만 조회된다. 아무것도 선택하지 않으면 `관광지`·`문화시설` 을 기본으로 한다. |
| AC-NP-9 | 각 장소의 거리 문구("850m · 도보 12분")는 서버가 만들어 내려준다 — 앱이 계산하지 않는다. |
| AC-NP-10 | 반경 안에 결과가 없으면 비어있음 상태를, TourAPI 조회가 실패하면 오류 상태를 표시한다. |

## 제약

- **API 경계 데이터는 `snake_case`** (C-7). 거리·상태 문구 같은 파생값은 서버가 만든다 (C-8).
- `image_url`·`tags` 는 TourAPI 등록 정보가 있을 때만 채워진다 — 없으면 `null` 이고 앱은 그 요소를 숨긴다.
- `status_label` 은 현재 항상 `null` — TourAPI 도 실시간 영업상태를 주지 않는다.
- 지도는 아직 실제 SDK 없이 공간 배치와 선택 동작만 검증하는 목 UI다 (지도 SDK 는 별도 결정).

## 열린 질문

- 지도 SDK, 비용, 위치 권한 문구와 배포 신고는 도입 전에 사람이 결정한다. (모바일 단계)
- 클러스터링과 "이 지역에서 다시 찾기"는 실제 지도 도입 시 결정한다.
